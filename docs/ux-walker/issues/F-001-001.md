# F-001-001: Signup crashes when SMTP is not configured in production

**Story**: STORY-001 (signup onboarding)
**Severity**: critical
**Category**: error-handling
**Criterion**: signup flow must not fail for a missing optional integration

## Description
`emailDevMode` was `NODE_ENV !== "production" && !SMTP_HOST`. Running the
production build (`npm start`) without SMTP configured made `sendEmail()`
attempt a real SMTP connection to port 587, which threw, and the signup
server action crashed with "Application error: a server-side exception has
occurred". The user account was created (transaction committed) but the user
never sees the dashboard — signup appears broken.

## Expected
Signup completes; the verification email is logged to the server console
with a clear "SMTP not configured" warning.

## Actual
500 on the signup action; user stranded on an error screen.

## Evidence
- Screenshot: shots/STORY-001/step-3-dashboard.png (error page)
- Server log: `Error: connect ECONNREFUSED 127.0.0.1:587` from nodemailer
- Source: `src/lib/env.ts` (emailDevMode), `src/lib/mail.ts` (sendEmail)

## Fix applied (same commit, unblocks the walk)
`emailDevMode = !env.SMTP_HOST` — environment-independent. Without SMTP the
email is logged in every environment instead of attempting a doomed
connection. Documented in env.ts.

## Remaining risk
A production deploy that *expects* SMTP but has a typo'd host now silently
falls back to console logging. Mitigation: the startup log prints a loud
warning when emailDevMode is on (added in mail.ts console output).
